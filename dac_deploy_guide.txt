1 Overview
SAP ECC/S4HANA maintains security with its role-based access controls, assisting organizations in preventing
unauthorized access and mitigating risk violations.
Pathlock DAC functions as an additional security layer for SAP users within the ECC/S4HANA application. This
extra layer, acting as an add-on, provides users with a granular approach to secure their ECC/S4HANA
environments.
1.1 Purpose
This guide provides information regarding Pathlock DAC deployment.
1.2 Mandatory Upgrade Requirements (Existing DAC Customers)
Customers upgrading from a DAC release earlier than DAC 2025 Q3 must run the Policy Migration Utility before
using the DAC Policy Studio
Mandatory Prerequisite:
Before configuring policies in DAC Policy Studio (/APPSDM/ABAC), you must execute the policy migration.
Skipping this step may lead to missing or inconsistent policy behavior.
Action Required:
1. 2. Execute migration using transaction - /APPSDM/POL_MIGRATE
After successful migration, proceed with configuration in DAC Policy Studio(/APPSDM/ABAC).
Note: This is a one-time step for upgrades only. This step is not required for first time installations.

3.3 Data Attributes BADI Implementation
In some scenarios masking / restriction needs to be done based on the context of another field. In some
scenarios, this required context may not be present on the screen and will then need to be derived
programmatically. BADI is used in such cases to derive the data context.
To understand this better, please refer to the below example:
Use Case 1 Mask the Material Description in table MAKT for those materials whose Material Group is ‘WARHEAD’.
In the above use case, the context for masking material description is Material group. However, the field material
group is not present in table MAKT and will then have to be derived programmatically based on material number.
To achieve this, we need to create a custom implementation for the Badi definition
/APPSDM/DATA_ATTRIBUTES. The attribute to be derived should be passed as the Badi filter. In the above
example, the attribute for material group will be assigned to the badi filter.
In this custom Badi implementation, the context value for data masking / restriction can be derived via code. The
attributes required to derive this context should be maintained under “Exposed Attributes”. When the user clicks
on exposed attribute button, a screen pops up which is where it should be maintained. The exposed attributes are
attributes which are already present on the screen and used to derive the context via code. In the above example,
the attribute for Material number is the exposed attribute.

3.7 Policy Simulator
The Policy Simulator enables policy administrators to simulate policy conditions for a specific SAP
transaction and the currently logged-in user. This allows validation and testing of complex policies in a
non-productive (test or quality) environment before deployment to production. The Policy Simulator can
be accessed using transaction code - /APPSDM/POL_SIMU
Important Behavior: If multiple policies are active in the system, only the policy explicitly selected and
provided to the Policy Simulator is evaluated during simulation. All other active policies are ignored,
even if they are enabled and applicable for the same transaction or user.
This ensures isolated and accurate testing of individual policies without interference from other active
configurations.

3.8 Data Discovery
Data Discovery is used to identify all SAP artifacts where a specific data definition is used. Based on
the selected search criteria, it retrieves the corresponding GUI applications, database tables, and
OData services.
Data Discovery supports searches using:
• Data Element
• Data Attribute
• Field Description
Only one search criterion can be selected at a time using the corresponding radio button.
Data Discovery can be executed using transaction code: /N/APPSDM/DISC
Search Scope and Behavior:
Based on the selected radio button, Data Discovery searches for:
• GUI Applications
• Database Tables
• OData Services
where the specified data element, data attribute, or field description is used.
Example: Data Discovery Using Data Element
1. 2. 3. On the selection screen, select the Data Element radio button.
Enter the required data element value for which data discovery needs to be performed.
Execute the report to retrieve all related GUI applications, tables, and OData services.
Similarly, users can perform Data Discovery by selecting:
• Data Attribute, or
• Description (description of the data element or a field)
